### 程序 3，第 1 部分：ISPC 基础（20 分中的 10 分） ###

阅读 ISPC 代码时，请记住：虽然代码看起来很像 C/C++，但 ISPC 的执行模型与标准 C/C++ 不同。与 C 不同，ISPC 程序的多个程序实例始终在 CPU 的 SIMD 执行单元上并行执行。同时执行的程序实例数量由编译器决定（会针对底层机器进行选择）。ISPC 程序员可以通过内置变量 `programCount` 获得这个并发实例数；ISPC 代码可以通过内置变量 `programIndex` 引用自身的程序实例编号。因此，从 C 代码调用一个 ISPC 函数，可以理解为启动了一组并发的 ISPC 程序实例（ISPC 文档称之为 gang）。这组实例全部执行完毕后，控制权才返回调用它的 C 代码。

例如，下面的程序结合普通 C 代码与 ISPC 代码，将两个含有 1024 个元素的向量相加。正如课堂上讨论过的，由于一个 gang 中的各个实例相互独立，并且执行完全相同的程序逻辑，因此可以通过 SIMD 指令实现来加速执行。

下面给出一个简单的 ISPC 程序。以下 C 代码会调用后面的 ISPC 代码：

    ------------------------------------------------------------------------
    C 程序代码：myprogram.cpp
    ------------------------------------------------------------------------
    const int TOTAL_VALUES = 1024;
    float a[TOTAL_VALUES];
    float b[TOTAL_VALUES];
    float c[TOTAL_VALUES]

    // 在此初始化数组 a 和 b。

    sum(TOTAL_VALUES, a, b, c);

    // sum 返回后，a + b 的结果保存在 c 中。

对应的 ISPC 代码：

    ------------------------------------------------------------------------
    ISPC 代码：myprogram.ispc
    ------------------------------------------------------------------------
    export sum(uniform int N, uniform float* a, uniform float* b, uniform float* c)
    {
      // 假设 N 能被 programCount 整除。
      for (int i=0; i<N; i+=programCount)
      {
        c[programIndex + i] = a[programIndex + i] + b[programIndex + i];
      }
    }

上述 ISPC 代码将数组元素的处理工作交错分配给各个程序实例。请注意它与程序 1 的相似之处：在那里，你把图像的不同部分静态分配给各个线程。

不过，比起考虑如何在程序实例之间分配工作（即工作如何映射到执行单元），只关注如何把问题划分为相互独立的部分，通常更方便，也更有表达能力。ISPC 的 `foreach` 结构提供了一种表达问题分解的机制。下面 ISPC 函数 `sum2` 中的 `foreach` 循环定义了一个迭代空间，其中所有迭代相互独立，因此可以按任意顺序执行。ISPC 负责将循环迭代分配给并发程序实例。`sum` 与下面的 `sum2` 之间的区别很细微，却非常重要。`sum` 是命令式的：它描述如何将工作映射到并发实例。而下面的示例是声明式的：它只指定需要执行的工作集合。

    -------------------------------------------------------------------------
    ISPC 代码：
    -------------------------------------------------------------------------
    export sum2(uniform int N, uniform float* a, uniform float* b, uniform float* c)
    {
      foreach (i = 0 ... N)
      {
        c[i] = a[i] + b[i];
      }
    }

<http://ispc.github.io/example.html>。教程中的示例程序与程序 3 在 `mandelbrot.ispc` 中的 `mandelbrot_ispc()` 实现几乎完全相同。在作业代码中，我们修改了 foreach 循环的边界，使实现更加直观。

程序 4 是一个 ISPC 程序，用于计算 2,000 万个介于 0 和 3 之间的随机数的平方根。它采用一种快速的迭代式平方根实现，使用牛顿法求解方程 ${\frac{1}{x^2}} - S = 0$。该实现以 1.0 作为初始猜测值。下图展示了对于 (0–3) 范围内的数值，`sqrt` 收敛到精确解所需的迭代次数。（对于该范围以外的输入，此实现不会收敛。）请注意，收敛速度取决于初始猜测值的准确程度。

## 程序 5：BLAS `saxpy`（10 分） ##

程序 5 实现了 BLAS（Basic Linear Algebra Subproblems，基本线性代数子问题）库中的 saxpy 例程。该例程在许多系统上被广泛使用，并经过高度优化。`saxpy` 计算一个简单的运算：`result = scale*X+Y`，其中 `X`、`Y` 和 `result` 都是包含 `N` 个元素的向量（程序 5 中，`N` = 2,000 万），`scale` 是一个标量。注意，`saxpy` 每涉及三个元素，就执行两次数学运算（一次乘法、一次加法）。`saxpy` 是一种*很容易并行化的计算*，具有可预测、规则的数据访问模式，以及可预测的执行开销。

**你需要完成的任务：**

1. 编译并运行 `saxpy`。程序会报告不使用任务的 ISPC 实现，以及使用任务的 ISPC 实现的性能。使用带任务的 ISPC 实现时，你观察到的加速比是多少？请解释该程序的性能表现。你认为它的性能还能大幅提高吗？（例如，你能否重写代码，使其获得接近线性的加速比？请回答能或不能，并说明理由。）
2. __附加题：__（1 分）注意，`main.cpp` 中消耗的总内存带宽的计算式为 `TOTAL_BYTES = 4 * N * sizeof(float);`。虽然 `saxpy` 只从 X 加载一个元素、从 Y 加载一个元素，并向 `result` 写入一个元素，但这里乘以 4 是正确的。为什么？（提示：想一想 CPU 缓存是如何工作的。）
3. __附加题：__（分值视具体情况而定）提升 `saxpy` 的性能。我们希望看到显著的加速，而不仅仅是几个百分点。如果成功，请描述你的方法，以及在这些系统上最理想的实现可能达到什么性能。另外，如果你成功了，请告诉课程工作人员，我们会很感兴趣。;-)

## 程序 6：加速 `K-Means`（15 分） ##
